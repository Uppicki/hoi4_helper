# Контракт обзора мира: известные страны и отношения с игроком

Статус: проект для согласования, версия структуры приложения 1.
Сбор, разбор и отображение этого раздела пока не реализованы.
Текущий мод V2 и его читатель продолжают работать по [контракту телеметрии](TELEMETRY_CONTRACT.md).

## Первый срез

Обзор показывает страны, существование которых подтверждённо известно игроку,
и проверенные отношения каждой из них со страной игрока на дату одного наблюдения.

Первый срез включает:

- код страны; название разрешается локально из игровых локализаций;
- войну со страной игрока;
- членство в одной фракции со страной игрока;
- подчинение стране игрока и обратное отношение: страна является её сюзереном.

Здесь «известная страна» означает подтверждённое знание игрока о её существовании.
Наличие TAG в локализации, определениях игры, общем переборе стран или в сырой
записи само по себе такого подтверждения не даёт. Название служит подписью к уже
допущенному TAG; наличие локализации не подтверждает его существование на дату наблюдения.

Гарантии, военный доступ, пакты, отношения между двумя чужими странами, оценки
сил и промышленности добавляются следующими небольшими расширениями после
проверки их получения и видимости. Отношения первого среза не используются для
вывода об отношении к игроку, намерениях ИИ или готовности вступить в войну.

## Граница знаний игрока

Путь данных:

1. Мод получает сведения в контексте страны игрока.
2. Правило видимости допускает конкретные сведения к записи в лог.
3. Читатель собирает целый кадр без смешения страны, даты и источника.
4. Чистое Dart-ядро проверяет происхождение и применяет политику знаний игрока.
5. Экран получает только разрешённую проекцию.

Политика знаний игрока имеет собственную версию и перечень проверенных правил.
Каждое правило связывает поле, способ чтения, страну наблюдателя, условия видимости
и подтверждённые игровые данные. Самой строке «visible=true» от источника недостаточно
для допуска: приложение должно знать и проверить соответствующее правило.

Если подтвердить видимость нельзя, поле остаётся unknown. Если нельзя подтвердить,
что игрок знает о существовании страны, запись страны целиком исключается из
разрешённой проекции. Число исключённых стран и их идентификаторы не передаются экрану.
Полезная частичная проекция допускается без раскрытия причины для конкретной
неизвестной страны.

В моде действует тот же принцип: сведения с неподтверждённой видимостью не выводятся
в game.log. Dart-слой дополнительно проверяет записи и не допускает новые или
неизвестные поля автоматически.

Отдельный уровень разведданных, членство во фракции или состояние войны сами по себе
не разрешают чтение остальных точных показателей чужой страны. Универсальный порог
разведки без проверки конкретного поля не назначается.

## Метаданные наблюдения

Это проект отдельной структуры PlayerWorldObservation, а не расширение снимка сейва.

| Поле | Требование |
| --- | --- |
| schemaVersion | 1 для этой структуры приложения; отдельно от версии строки мода |
| gameDate | Дата из префикса кадра, проверенная по правилам телеметрии, включая час 24 |
| playerTag | Единственная страна наблюдателя; TAG формата, поддерживаемого читателем |
| receivedAt | Время принятия полного кадра приложением; не время события в игре |
| logSource | Конкретный источник game.log |
| modRecordVersion | Подтверждённая версия формата, способная передать объекты мира |
| gameDataId | Проверенная идентичность игровых данных и модов, либо неизвестно |
| visibilityPolicyId | Версия политики и правил видимости, применённых Dart-ядром |
| countriesCoverage | Полнота перечня допущенных стран в объявленной области |
| relationsCoverage | Полнота набора проверок отношений в объявленной области |
| scopeId | Проверенная область перечисления; в первом срезе только отношения со страной игрока |
| supportedRelationFields | Явный перечень поддерживаемых полей отношений; неизвестный состав не угадывается по строкам |
| declaredCountryCount, declaredRelationCount | Число переданных разрешённых записей; без подсчёта исключённых скрытых стран |
| countries | Записи разрешённых стран; без повторяющихся TAG |
| relations | Отношения игрока с разрешёнными странами; без повторяющейся пары |
| campaignId, saveId | Неизвестны; не заполняются по пути лога, TAG или дате |

При неизвестных игровых данных применяется только политика, чья применимость
проверена отдельно; неизвестная совместимость не считается успешной проверкой.
Без применимой политики разрешённый раздел мира остаётся недоступным.

Путь лога, последовательность кадров и локальный номер сброса читателя не доказывают
идентичность кампании. Новая проекция полностью заменяет старую; неизвестные поля
не дополняются из предыдущего дня или другого источника.

## Страны и отношения

Страна представлена TAG и доказательством допустимости её присутствия в проекции.
Доказательство ссылается на проверенное правило политики; оно не содержит скрытых
значений. Страна игрока входит в разрешённый перечень при подтверждённом playerTag.

Названия стран не являются постоянными идентификаторами. Если конкретный вариант
названия нельзя разрешить по разрешённым сведениям, интерфейс показывает TAG.
Идеология не считывается из скрытых данных ради выбора локализованного названия.

Для каждой пары (playerTag, otherTag) предусмотрена одна запись.
otherTag отличается от playerTag и присутствует в countries.

| Поле отношения | Значение true | Кандидат способа чтения |
| --- | --- | --- |
| atWarWithPlayer | Страны находятся в состоянии войны друг с другом | has_war_with |
| inFactionWithPlayer | Страны состоят в одной фракции | is_in_faction_with |
| subjectOfPlayer | Другая страна является подчинённой страны игрока | is_subject_of в области другой страны |
| overlordOfPlayer | Страна игрока является подчинённой другой страны | is_subject_of в области страны игрока |

Названия триггеров сверены с локальным triggers_documentation.md.
Направление каждой проверки фиксируется и проверяется тестами.
Значения atWarWithPlayer и inFactionWithPlayer симметричны только при одинаковых
условиях наблюдения; subjectOfPlayer и overlordOfPlayer не взаимозаменяемы.
Обратная запись (otherTag, playerTag) в первом срезе не хранится.

Это кандидаты получения факта. Видимость результата в интерфейсе игры и конкретная
область ROOT/PREV ещё должны быть подтверждены на обезличенных реальных примерах.
Ни одно правило первого среза пока не считается проверенным для рабочего мода.

## Значение поля и неизвестность

Для новых полей используется отдельная модель знания. Существующий
TelemetryValueStatus V1/V2 этим проектом не изменяется.

| Состояние | Значение |
| --- | --- |
| value | Есть проверенное допустимое значение и применимое правило видимости; false так же значимо, как true |
| unknown | Сведения не наблюдались либо их видимость/происхождение не подтверждены; значения нет |
| missing | Поддерживаемое поле заявлено в составе записи, но в завершённой структуре отсутствует |
| unsupported | Подтверждённая версия источника не поддерживает поле или раздел |
| invalid | Поле присутствует, но значение не соответствует типу или контракту |

value требует payload типа bool и ссылку на применённое правило политики.
Все остальные состояния запрещают payload. Ошибочная или скрытая исходная величина
не сохраняется в разрешённой проекции. Неизвестные ключи не допускаются на экран
путём автоматического расширения структуры.

Отрицательный ответ допускается только после явной допустимой проверки.
Отсутствующая строка страны, пары или поля не превращается в false.
При утрате видимости прежнее значение исчезает из нового наблюдения.
Если позже добавятся оценки численности, их диапазоны потребуют отдельного контракта;
они не преобразуются в точное число или середину диапазона.

Иллюстративный фрагмент разрешённой проекции, все данные вымышлены:

~~~json
{
  "playerTag": "ALB",
  "countries": [
    {"tag": "ALB"},
    {"tag": "ITA"}
  ],
  "countriesCoverage": "partial",
  "relationsCoverage": "partial",
  "relations": [
    {
      "otherTag": "ITA",
      "atWarWithPlayer": {
        "status": "value",
        "value": false,
        "ruleId": "fixture.player-visible-war.v1"
      },
      "inFactionWithPlayer": {"status": "unknown"},
      "subjectOfPlayer": {"status": "unsupported"},
      "overlordOfPlayer": {"status": "missing"}
    }
  ]
}
~~~

Это фрагмент для объяснения состояний: обязательные метаданные и доказательства
допуска стран опущены. Он не является полным кадром или доступной сегодня командой импорта. Правило fixture предназначено только для синтетического примера.

## Полнота и публикация

Полнота доставки кадра и полнота знаний — разные свойства.
Целый кадр может содержать частичный перечень стран и unknown-поля.

Для каждого раздела объявляются поддерживаемые поля, область перечисления
и состояние покрытия: complete, partial, unknown или unsupported.
complete допустимо только для явно названной и проверенной области. Например,
полное перечисление проверенных отношений с выбранными странами не означает
полный список стран мира.

Заявленный состав и число записей должны совпадать с доставленными.
Частичный по доставке кадр, повтор TAG/пары, ссылка на отсутствующую страну,
невалидный playerTag, несовместимая схема или смешанная дата/страна не публикуются.
Нарушение типизации отдельного поля оставляет invalid без payload, если границы
и идентичность целого кадра подтверждены.

Пустой список с покрытием partial, unknown или unsupported не означает, что
других стран или отношений нет. Даже complete не разрешает достраивать false
по отсутствующей записи: отрицательные ответы передаются явно.

Начало кадра другой страны, откат/повтор даты и обнаруженная смена лога сбрасывают
прежнюю проекцию по правилам читателя. Во время неполной записи того же потока
можно показывать только последнее полное наблюдение со своей датой и статусом ожидания.
При паузе новых наблюдений нет.

## Совместимость с действующей телеметрией

V1 и V2 не передают объекты стран мира и отношения: весь новый раздел для них
имеет состояние unsupported, а не пустой мир или отсутствие отношений.
Их числовые показатели страны игрока продолжают читаться по действующему контракту.

Будущая версия записи мода должна явно объявлять состав разделов и полей,
границы кадра и правила экранирования строк. Номер версии и конкретный синтаксис
game.log в этом документе не назначаются до проверки способа получения сведений.
Неизвестная версия не интерпретируется как V2.

Первый срез используется только для просмотра. Допуск к рекомендациям и экспорту
потребует отдельной проверки происхождения и пригодности для конкретного расчёта.

## Проверки перед реализацией и приёмкой

1. Подтвердить правило допуска страны и видимость каждого из четырёх отношений
   в интерфейсе одиночной игры; сохранить только минимальные обезличенные примеры.
2. Проверить триггеры, области и формат реальных строк установленной игры.
   Повторять проверку для изменившихся игровых данных, не закрепляя номер версии игры.
3. Проверить явные true/false и все четыре состояния без значения.
4. Проверить направление подчинения, дубли и ссылки на отсутствующие страны.
5. Проверить неполную доставку, неизвестные версии/правила, смену страны,
   откат даты, пропадание страны из нового разрешённого перечня и утрату видимости.
6. Проверить слой знаний на двух сырых входах, различающихся исключительно
   скрытыми данными: разрешённая проекция должна совпадать, включая TAG и счётчики.
   Будущие рекомендации и экспорт должны сохранять тот же инвариант.
7. Проверить, что частичное покрытие и отсутствие записей не порождают false,
   а состояния нового раздела не меняют работу V1/V2.

Подтверждено в рамках подготовки проекта: наличие трёх названных триггеров
в локальной документации установленной игры и отсутствие объектов мира в текущем
формате V2. Правила видимости, реальные строки расширенного формата и поведение
нового раздела в запущенной игре ещё не проверены.

После согласования этого проекта следующий шаг — проверить в игре правило
видимости страны и одно поле atWarWithPlayer, затем реализовать минимальный
проход «мод → читатель → знания игрока → экран» для этого поля.
